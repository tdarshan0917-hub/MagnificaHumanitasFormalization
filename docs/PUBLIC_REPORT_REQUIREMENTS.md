# The required public report

User requirement recorded 2026-11-01: the completed work must have a formal, intelligible report for an ordinary reader. Code without an understandable account of its results is an incomplete project.

## Final deliverable

A polished PDF, approximately 4–6 pages, alongside the technical companion paper. Length may be adjusted for clarity; the report cannot be replaced by a Lean README or a list of theorem names.

The first page answers: What did we investigate? What did we learn? Why could it matter? What has not been established?

## Required explanations

For each major finding:

1. State the everyday question in one sentence.
2. Describe a concrete case without notation.
3. State the result directly.
4. Name the assumptions in ordinary language.
5. Explain a practical implication without claiming actual adoption or measured benefits.
6. Say what the result does not show.

Explain counterexample as "an example showing that one promise does not guarantee another." Explain formal verification as "a computer checks that the conclusion follows from the written rules." Use specialist terms only when needed and define them immediately.

Include the three agreed cases, a brief explanation of differing readings of the source, paragraph references, and a short technical-method note. The reader should not have to open code to understand any principal conclusion.

## Quality checks before final release

- Every public finding maps to a verified technical result or an explicitly labeled unresolved question.
- Every hypothetical fact is labeled as hypothetical.
- No "proved ethical," "certified safe," "proved the encyclical true," or "real-world compliance certified" claim.
- No theorem-count inflation or unsupported novelty claim.
- Tables and diagrams, if used, must clarify a particular question.
- Check the PDF visually and verify the extracted text.
- Invite reader feedback when available; do not claim an ordinary-reader comprehension test took place without actually conducting one.

The current prototype report is an early demonstration of this format. It does not replace the final report.
